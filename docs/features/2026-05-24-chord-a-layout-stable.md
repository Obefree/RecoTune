# Практика: стабильная строка с аккордом A

**Дата:** 2026-05-24  
**Файлы:** `src/screens/ChordsScreen.tsx`

## Зачем

После [2026-05-24-practice-scroll-chord-a.md](./2026-05-24-practice-scroll-chord-a.md) одиночные аккорды **A–G** получили отдельный chip (`minWidth`, больший padding). Из‑за этого колонка над словом была шире/выше, чем у **Am** / **C#**, и при `flexWrap` строка слегка «прыгала».

## Было → стало

| Область | Было | Стало |
|--------|------|--------|
| `chordChipTextStyle` | Разный padding/`minWidth` для `A` vs `Am` | Один стиль chip; ширина колонки — у слота |
| Слот над словом | Пустой `height: 21` vs chip разной высоты | `CHORD_INLINE_ROW_H` + `CHORD_INLINE_SLOT_MIN_W` на всех chord-колонках |
| Строка только аккордов | Разная ширина chip | Тот же фиксированный слот |

`chordLyricsNormalize` не менялся — нормализация детерминирована (`npm run verify-chord-normalize`).

## Как проверить

1. Практика → текст с `A D E`, `[A]слово`, смесь `Am` и `A` в одной строке.
2. Сравнить соседние строки: вертикальный ритм и переносы не сдвигаются при смене аккорда на **A**.
3. `npm run verify-chord-normalize` — PASS.
