# Melody: ось времени на графике высоты

**Дата:** 2026-05-24

## Зачем

После `453e529` нота на графике Melody всё ещё могла **ускоряться и уезжать вправо** за 20–30 с пения. Пользователь: «раньше простой интерфейс работал, сейчас тупит».

## Причина

| Фактор | Эффект |
|--------|--------|
| Гибридная раскладка X | До ~4 с — **по индексу** (`i × 14px`); дальше — **по времени**, но `contentW` всё равно растёт с числом точек |
| `totalW` без запаса под playhead | `hScroll` упирался в `maxScroll` → хвост визуально не на 58%, а у правого края и «догонял» скачками |
| Снятие cap 9 px (`453e529`) | Убрало отставание скролла, но не убрало **рост X быстрее реального времени** в index/clustered режимах |

Throttle 100 ms в `useSungNoteHistory` ок; ломала **геометрия оси X**, не детектор.

## Файлы

| Файл | Изменение |
|------|-----------|
| `src/components/FrequencyChart.tsx` | `timeAxis`: X = `(ts − t₀) × px/ms`, `totalW` с `scrollRightPad` под якорь playhead |
| `src/components/MelodyPitchChart.tsx` | `timeAxis` для Melody |
| `src/hooks/useSungNoteHistory.ts` | без изменений (throttle 100 ms) |

## Было → стало

| Было | Стало |
|------|--------|
| X от номера точки / сжатое время + растущий `contentW` | X только от `ts` (14 px / 100 ms при zoom 2×) |
| `totalW ≈ (n−1)×cell` | `totalW ≥ lastX + (ширина − playhead) + запас` |
| Скролл два `useEffect` | Один follow + clamp |

**Не трогали:** Tuner / Chords (`timeAxis` выключен), `TunerEngine`, voiced gate.

## Проверка

1. Melody → START → медленная гамма 5 нот ~30 с: точка у playhead (~58%), без разгона вправо.
2. Pinch zoom — скорость по времени масштабируется с `hZoom`.
3. Тюнер — график как раньше (legacy layout).
