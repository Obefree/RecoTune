# Melody: распознавание нот — диапазон, повторы (onset), короткие ноты

Дата: 2026-06-24

## Зачем

Жалоба пользователя: «просто часть нот не распознаются, хотя частоты точно доходят
до датчиков». То есть тюнер ловит высоту (видно на графике), но контурная
транскрипция (`pitch frames → note segments`) не превращает часть валидных кадров
в ноты.

## Корень проблемы (что именно теряло ноты)

Кадры с высотой попадают в RN только когда движок уже прошёл свои гейты
(`rms > 0.006` → `signal > 0.048`, `yin ≤ 0.2`). Значит RMS/YIN-гейты внутри
транскрипции ноты не режут. Ноты терялись на трёх шагах:

1. **Диапазон кадра уже движка.** Движок (`TunerEngine` melody) отдаёт высоту для
   **70–1200 Hz**, а кольцо кадров (`PITCH_FRAME_RING`) принимало только
   **80–1000 Hz**. Низкие (70–80) и особенно высокие (1000–1200) ноты доходили до
   детектора, но молча отбрасывались на гейте кадра.
2. **Повторы одной высоты сливались (нет onset).** `mergeNearSameMidiSegments`
   склеивал соседние сегменты с одинаковым midi (gap<130 ms), а разрез был только
   по скачку высоты или паузе 220 ms. Поэтому `C-C-C` спетое подряд → одна длинная
   `C`. Известное слабое место.
3. **Короткие/быстрые ноты выкидывались.** `minSegmentMs=165`, в основном цикле
   `continue` при `dur<165 && frames<3`, а `absorbShortFragments` поглощал
   фрагменты <220 ms / ≤3 кадров в соседей. Быстрая нота просто исчезала.

## Что изменено

| Файл | Было → стало |
|---|---|
| `src/utils/pitchFrame.ts` | `PITCH_FRAME_RING` диапазон **80–1000 → 70–1200 Hz** (совпадает с движком) |
| `src/utils/melodyTranscription.ts` | `minSegmentMs` 165→**110**; `shortFragmentMs` 220→**150**; `shortFragmentFrames` 3→**2** |
| `src/utils/melodyTranscription.ts` | новый **energy-onset** разрез повторов: `splitRawSegments` отслеживает огибающую (release ниже `0.62×peak` → re-attack выше `0.9×peak`) и начинает новую ноту той же высоты |
| `src/utils/melodyTranscription.ts` | `RawSegment.onsetStart` — onset-сегменты **не сливаются** обратно в `mergeNearSameMidiSegments` и не поглощаются в `absorbShortFragments` |
| `src/utils/melodyTranscription.ts` | основной цикл: дроп только 1-кадровых глитчей (`frames < 2`), а не реальных коротких нот |
| `src/screens/MelodyScreen.tsx` | строка статистики показывает `голос N` (voiced frames) — видно «дошло кадров → стало нот»; удалены мёртвые стили `detectorDebugChip`/`detectorDebugText` |
| `tools/verify-melody-transcription.mjs` | новый smoke-тест: диапазон, разрез повторов, удержанная нота = 1, короткая нота жива, 1-кадровый глитч ≠ нота |

## Как теперь работают повторы одной ноты (C-C-C)

Высота при повторе не меняется, поэтому разрез по скачку не срабатывает. Вместо
этого внутри сегмента отслеживается громкость: если амплитуда **просела** (ниже
`0.62 × текущего пика`), а затем **вернулась** (выше `0.9 × пика`) при той же
высоте и сегмент уже длиннее `90 ms` — это новая атака, начинается отдельная нота.
Такой сегмент помечается `onsetStart` и его уже не склеит обратно merge-шаг. Если
между повторами есть явная пауза (>130 ms), как и раньше работает разрез по
тишине — два пути дополняют друг друга, не дублируются.

## Воспроизведение / PLAY

Форма сегментов (`startMs/endMs/midi`) не менялась —
`buildMelodyPlaybackPayloadFromSegments` и нотный стан работают как прежде, нот
становится больше там, где раньше терялись.

## Проверка

```
npm run verify-melody-transcription
```

На устройстве: START → спеть гамму вверх с высокими нотами и подряд `до-до-до` →
STOP. В строке под графиком `кадры N · голос M · ноты K` — `ноты` должны
совпадать с тем, что слышно; повторы дают отдельные блоки на ленте/стане.
