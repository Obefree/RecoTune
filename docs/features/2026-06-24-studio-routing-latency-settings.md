# Studio: маршрут звука, латентность, честный мик/выход, компактные настройки

**Дата:** 2026-06-24

## Зачем

Жалобы: латентность «не работает», выбор микрофона не работает, выход на AUX не работает,
плюс дубли/мёртвый код и громоздкие настройки.

## Диагностика (факт vs ограничение платформы)

| Жалоба | Что нашли |
|--------|-----------|
| Задержка не применяется | `resetAllOffsets` (применить задержку ко всем дорожкам) был **написан, но не подключён** ни к одной кнопке. Слайдер менял только дефолт следующей записи |
| Earpiece/маршрут сбрасывается на воспроизведении | solo и Play all вызывали `applyPlaybackAudioMode()` (`playThroughEarpieceAndroid:false`), затирая ручной маршрут «Трубка» из настроек — **реальный баг** |
| Микрофон не выбирается | expo-av на Android 9+ реально умеет (`setPreferredDevice`, для BT `startBluetoothSco`). Ошибка молча гналась в `catch {}` — пользователь не видел отказа. На Android < 9 не поддерживается |
| AUX/выход не переключается | expo-av **не умеет** форсить выход на конкретное устройство (нет API). Реально форсится только «Трубка». BT/AUX/динамик — системный маршрут (звук идёт туда сам, когда подключено). 5 «кнопок выхода» вводили в заблуждение |

## Что сделано

| Файл | Изменение |
|------|-----------|
| `src/utils/studioAudioRouting.ts` | `applyStudioAudioMode` (не-запись) — единый сеттер playback-сессии: `staysActiveInBackground:true`, честный `playThroughEarpieceAndroid` (больше не затирается). `applyRecordingInput` возвращает статус (`applied`/`missing`/`rejected`/`default`) вместо «молчать в catch» |
| `src/screens/StudioScreen.tsx` | solo и Play all переведены с `applyPlaybackAudioMode()` на `applyStudioAudioMode(routing,{recording:false})` (dedupe + фикс earpiece). Подключён `resetAllOffsets` → кнопка «Применить N мс ко всем дорожкам 2+». При отказе ОС в выбранном мике — честная подсказка под таймером записи. Удалён мёртвый CSS (`scrubThumb`, `latencyLabel`, `routeInputGroup*`, `routeInputRow*`, `modalOverlay`, `modalBox`, …) |
| Настройки (модалка) | Переразбиты на пронумерованные секции: ① Качество записи · ② Задержка дорожек (+пресеты провод/BT, «применить ко всем») · ③ Звук — микрофон и выход. Честный текст: принудительно только «Трубка», остальное — авто-маршрут системы + пресет задержки |

## Было → стало

| Область | Было | Стало |
|---------|------|--------|
| Audio-сессия Studio | 2 сеттера (`applyPlaybackAudioMode` + `applyStudioAudioMode`), конфликт по earpiece | один `applyStudioAudioMode`, маршрут «Трубка» сохраняется на воспроизведении |
| Применение задержки | только к следующей записи | кнопка применяет ко всем дорожкам 2+ |
| Выбор мика | `catch {}` молча | статус + честная подсказка, если ОС отказала |
| Выход AUX/BT | 5 кнопок как будто переключают | честно: авто-маршрут + пресет задержки; форсится только «Трубка» |
| Мёртвый код | `resetAllOffsets` + ~11 неиспользуемых стилей | подключено / удалено |

## Проверка на устройстве

- Play all / solo с подключённым AUX или BT — звук идёт в устройство; «Трубка» в ручном режиме звучит у уха и не сбрасывается.
- Настройки → ② задержка → «Применить ко всем»: смещения дорожек 2+ обновляются, Play all сразу пересинхронизируется.
- Настройки → ③ выбрать BT-микрофон (Android 9+) → запись пишет с него; если ОС отказала — подсказка под таймером.

## Ограничения (платформа)

- Принудительный выход на конкретный динамик/AUX/BT через expo-av невозможен — только системный маршрут и «Трубка». Это отражено в UI честно (без заглушек).
- Выбор микрофона: Android 9+ и iOS; на Android < 9 — системный по умолчанию.
