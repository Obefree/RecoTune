# Melody: одна схема распознавания, единый timebase, фикс слияния разных нот

Дата: 2026-07-05

## Зачем

Жалоба (#4): распознавание мелодии и её воспроизведение «работают очень странно —
то хорошо, то плохо». Постоянные симптомы:

1. **По-разному от прогона к прогону** на одном и том же входе — пользователь
   подозревал «наслоение разных функций».
2. **Такты / общая продолжительность** всегда неверные.
3. **Разные ноты** иногда распознаются как **одна**.

## Корень проблемы

### 1. Две схемы распознавания + скрытое переключение (run-to-run variance)

`MelodyScreen` одновременно гонял **два** нотных детектора на один и тот же живой
вход:

- **контур** — `transcribeFromPitchFrames(pitchFrames)` (source of truth по D15);
- **классика** — `SungNoteDetector` из `useSungNoteHistory` (`registeredEvents`).

Какая схема управляет нотами, станом, анализом и воспроизведением, решал порог
уверенности:

```
useContourRecognition = (mode==='contour' || file || hum)
  && isTranscriptionConfidenceOk(transcription)   // confidence >= 0.25
```

`confidence` болтается около порога → на почти одинаковых дублях **флип** между
двумя пайплайнами. А у них **разный timebase**: контур считает длительность как
`endMs − startMs` сегмента, классика — по межонсетным интервалам с искусственным
«хвостом» последней ноты (600–1500 ms) и одиночной ноты (800–1200 ms). Отсюда
«то хорошо, то плохо» и «продолжительность всегда другая».

Дополнительно классика ставила `ts = commitTs` (момент **подтверждения** ноты
после ~120 ms стабильности), а не старт → онсеты и BPM (`estimateRhythm`) были
смещены.

### 2. Стан и воспроизведение считались из разных представлений (такты/длительность)

`buildStaffPlaybackTimings` брал тайминги через `staffIndicesPerPlaybackNote(...)`
— группировку одинаковых по высоте событий в пределах 60 ms (нужна только для
классики, где playback склеивает джиттер-дубли). Для контура ноты 1:1 с
сегментами, но группировка всё равно могла слить → индексы стана уезжали →
неверные позиции playhead и длительности «тактов».

### 3. Слияние разных нот в одну

`absorbShortFragments` склеивал `prev + cur + next`, когда `prev` и `next` — одной
высоты, **не проверяя высоту самого `cur`**. Короткая, но **другая** нота между
двумя одинаковыми (`A – C – A`) уничтожалась.

## Что изменено (было → стало)

| Файл | Было → стало |
|---|---|
| `src/hooks/useSungNoteHistory.ts` | Живой `SungNoteDetector` **удалён** из мелодии (второй детектор). Хук отдаёт только pitch-кадры + график. `registeredEvents` теперь наполняется **только** `loadSnapshot` (загрузка сохранённой мелодии). Удалены `detectorRef`, импорт `SungNoteDetector`/`mergeJitterNotes`, `MAX_NOTES` |
| `src/screens/MelodyScreen.tsx` | `useContourRecognition = transcription.segments.length > 0` — **одна** схема (контур). Убран `recognitionMode` (контур/классика), убран флип по `isTranscriptionConfidenceOk`, убран UI-тумблер. Сохранение мелодии — из `activeEvents` (контур), а не из мёртвого `sungNotes` |
| `src/utils/melodyPlayback.ts` | `buildStaffPlaybackTimings`: при совпадении числа нот (контур, 1:1) — прямое сопоставление стан ↔ playback по индексу, без группировки 60 ms |
| `src/utils/melodyTranscription.ts` | `absorbShortFragments`: мост `prev+cur+next` только когда `cur` **близок по высоте** (`≤ shortFragmentMaxSemitones`) к окружению; иначе короткая другая нота остаётся отдельной |
| `tools/verify-melody-transcription.mjs` | Зеркалит guard; новый кейс `A4 · C5(коротко) · A4` → 3 ноты (разные ноты не сливаются) |

`SungNoteDetector` **не удалён из репозитория** — он по-прежнему используется на
вкладке Тюнер (`TunerScreen`), это самостоятельный поток. Удалено только его
дублирующее применение в мелодии.

## Почему это чинит жалобы

- **Run-to-run:** нет второго детектора и нет порогового флипа — контур (как на
  графике) всегда единственный источник нот/стана/анализа/воспроизведения.
- **Такты / продолжительность:** один timebase (границы сегментов). Воспроизведение
  и нотный стан индексируются 1:1 с распознанными нотами.
- **Разные ноты → одна:** короткая другая нота между двумя одинаковыми больше не
  поглощается.
- **no-stubs:** если контур не дал сегментов — честно пусто (без подмены вторым
  детектором).

## Проверка

```
npm run verify-melody-transcription
npx tsc --noEmit
```

На устройстве: START → спеть фразу с повторами и быстрой «чужой» нотой между
одинаковыми → STOP. Под графиком `кадры · голос · ноты`; PLAY звучит по тем же
нотам и длительности, что на стане; повторные прогоны дают тот же результат.
