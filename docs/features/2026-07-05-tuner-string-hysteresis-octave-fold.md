# Tuner: стабильная целевая струна (гистерезис) + октавная свёртка вместо дёрганья

**Дата:** 2026-07-05

## Зачем

После запуска тюнера в Expo Go (SDK 54) осталось два бага:

1. **Целевая струна прыгала вниз.** Пока высоту поднимаешь — норм, но у правильной/высокой
   ноты подсветка струны «сваливалась» на струну **ниже** (толще), а не держалась на нужной.
2. **График и стрелка дёргались.** Струна «не держала» высоту, частотный график превращался
   в «кашу» — всё скакало, настраивать тяжело.

## Что диагностировано (не угадано)

| Симптом | Корень |
|---------|--------|
| Струна-цель прыгает на нижнюю | `activeStringNumber` считал `findNearestString` **каждый кадр без гистерезиса** по «гуляющей» EMA-частоте; готовый `findNearestStringWithHysteresis` **не был подключён**. Плюс `centsToStringTarget` сворачивает ±1 октаву → гармоника/суб-гармоника детектора отображается на **другую** (нижнюю) струну |
| «Каша» и дёрганье графика/стрелки | Октавные ошибки детектора (×2, ÷2 …) держались **несколько кадров**. Одно-кадровый `OUTLIER_CENTS_JUMP` пропускал только **первый** кадр скачка, а дальше синхронизировался с уже «улетевшим» значением → `smoothMidi` травился на октаву → нота/центы/график прыгали |
| Двойное сглаживание | На график шёл **отдельный** EMA (`CHART_MIDI_EMA`) поверх 1€, т.е. второй путь сглаживания рядом со стрелкой (лаг + рассинхрон путей) |

## Что сделано (архитектура, не подкрутка констант — D13)

| Файл | Изменение |
|------|-----------|
| `src/utils/tunerDisplay.ts` | **Октавная свёртка**: если сырой отсчёт после сдвига на целые октавы попадает в ±`OCTAVE_FOLD_SEMITONES` (1.5) от отслеживаемой высоты — это октавная/гармоническая ошибка, сворачиваем на текущую высоту (не «пропуск-удержание», без лага). Устойчиво к **длящимся** флипам. Одно-кадровый `OUTLIER_CENTS_JUMP` оставлен только для **не-октавных** глитчей. Hz-читалка берётся из свёрнутого значения. Убран **второй** EMA графика (`CHART_MIDI_EMA`, `chartMidiDisplay`) — график берёт тот же `smoothMidi`, что и стрелка (**один** путь сглаживания) |
| `src/screens/TunerScreen.tsx` | Подсветка струны теперь через **`findNearestStringWithHysteresis`** с закоммиченной целью (`committedStringRef` + `activeStringNumber` state): цель **держится**, пока настраиваешь струну, и меняется только при явном переходе. Сброс при тишине/сигнале/старте/стопе и **смене строя**. Убран мёртвый пер-кадровый расчёт по `findNearestString` |
| `tools/verify-tuner-display.mjs` | Зеркалит новую логику (свёртка вместо skip, без `CHART_MIDI_EMA`) + новые кейсы: **длящийся** октавный флип держит ноту/стрелку; не-октавный переход (кварта) всё ещё отслеживается |

## Было → стало

| Область | Было | Стало |
|---------|------|--------|
| Выбор струны | `findNearestString` каждый кадр, без гистерезиса | `findNearestStringWithHysteresis`, закоммиченная цель |
| Октавная ошибка детектора | skip 1 кадра → длящийся флип травит фильтр | свёртка на отслеживаемую высоту (любое число кадров) |
| Путь графика | 1€ + отдельный EMA `CHART_MIDI_EMA` | тот же `smoothMidi`, что у стрелки (один путь) |
| Hz-читалка | из сырой (октавно-шумной) частоты | из свёрнутой (фундаментальной) |

## Проверка

```bash
cd RecoTune
npm run verify-tuner-display
npm run verify-tuner-chart
npm run verify-pitch-chart
npx tsc --noEmit
```

На устройстве: Tuner → START → настрой струну вверх до нужной/чуть выше — подсветка струны
**держится** на цели, не сваливается на нижнюю; стрелка и график ровные, без «каши» и октавных
скачков; смена струны (после паузы) переключает цель корректно; бас (E1/B0) держится.
