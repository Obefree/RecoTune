# Chords: song-list duplicates («повторы») + доступ к справочнику базовых аккордов

**Дата:** 2026-07-26 · **Файлы:** `src/db/songLibrary.ts`, `src/screens/ChordsScreen.tsx`, `tools/verify-song-library-dedupe.mjs`

## Контекст

После D24 (тот же день) Alex сообщил, что «повторы аккорды» всё ещё есть, и попросил «хотя бы базовый список обычных аккордов». Сообщение было в русской раскладке-на-английской, расшифровано как выше — **интерпретация помечена как предположение**, см. `decisions.md` D25.

## A) Повторы в «БАЗА ПЕСЕН» (подтверждённый баг)

### Проверено и НЕ является багом

Слои D24 (`{mode==='practice' && !showLibrary}`, единый back-обработчик `onHardwareBack`, `didInitialLibraryOpenRef` — открытие библиотеки один раз) — прочитаны заново построчно, дублирующего рендер-пути или ghost-модалки не найдено. Второй блок с тем же условием на `!showLibrary` (строка ~3424) — это нижний док Mic/REC, отдельный **сиблинг**-контейнер (комментарий в коде объясняет: привязан к низу экрана, а не колонки практики), не дубликат UI.

### Найден и подтверждён другой баг: дубли строк в списке песен

`listSongs()` (`src/db/songLibrary.ts`) отдаёт **все** строки таблицы `songs` без дедупликации. Легаси-сид (`sNNN`, 32 песни) и bundled pesni.ru архив (`pesni_ru_*`, 1113 записей, D22) хранятся под разными `id`, поэтому одна и та же песня может лежать в таблице **дважды** — в «БАЗЕ ПЕСЕН» и в поиске (`searchSongsSmart` строится поверх `listSongs()`) она показывалась **двумя одинаковыми строчками**. Подтверждено на реальных бандлах: **15 дублей**, например:

| id 1 | id 2 | Песня |
|------|------|-------|
| `s007` | `pesni_ru_blowin-in-the-wind` | Bob Dylan — Blowin' in the Wind |
| `pesni_ru_agidel-belaya-reka` | `pesni_ru_agidel-belaia-reka` | ДДТ — Агидель (Белая река) |
| `pesni_ru_alkogol` / `-1` | — | Сплин — Алкоголь (опечатка «Алкогол» без мягкого знака) |

Причина внутри pesni.ru-архива — ingestion (`tools/ingest-pesni-chordpro.mjs`) иногда цепляет одну песню под двумя написаниями заголовка (пропущенный мягкий знак / й, транслит вариант). Корень ingestion не трогали (не в рамках задачи), почищен user-facing симптом.

### Фикс

`dedupeSongRows()` в `songLibrary.ts` — группирует строки по `combinedArtistTitle(artist, title)` (та же нормализация, что уже используется для дедупа результатов поиска в `ChordsScreen.applyLibSearchResults`, т.е. никакой новой схемы), при коллизии оставляет **не-pesni** (curated) строку. Единая точка (`listSongs()`) чинит и список, и поиск сразу, без второго пути.

Тест: `npm run verify-song-library-dedupe` — синтетические кейсы + прогон на реальном bundle (ловит будущие дубли как регрессию).

## B) «Базовые аккорды» — фича уже существует, была спрятана

Полный проверенный справочник аккордов (гитара/укулеле, все лады из таблицы инструмента, честное «нет схемы» без фейков — см. `docs/features/2026-05-29-chord-reference-dictionary.md`) **уже реализован**: `src/data/basicChordCatalog.ts` + `chordShapes.ts` + модалка «СПРАВОЧНИК» в `ChordsScreen.tsx`.

**Проблема:** кнопка «Справочник» была видна только внутри `mode === 'practice' && !showLibrary` — то есть только когда пользователь **уже закрыл** список песен (который D24 теперь открывает автоматически при заходе на вкладку). Без выбранной песни справочник было не найти.

**Фикс (без дублирования):** добавлена иконка-кнопка (🔲 grid-outline, тот же значок, что и в баре практики) в шапку модалки «БАЗА ПЕСЕН» — открывает тот же `showBasicChordsModal`, не создавая нового экрана/данных/компонента. Один тап из первого экрана Chords → полный список аккордов (маж/мин/7/sus/dim/aug/…) с грифами.

1. «БАЗА ПЕСЕН» → пролистать/поискать «Blowin'» — одна карточка Bob Dylan, не две.
2. Открыть Chords → сразу (без выбора песни) тап на иконку 🔲 в шапке списка → «СПРАВОЧНИК» открывается, лады C…B, гитара/укулеле переключаются.
3. Из практики кнопка «Справочник» внизу работает как раньше (не тронута).
